### B-1. README 979行目「turboでの生成は常にblocking判定になります」が現状と合っているか

**未確認。GPUが要ります。** 今日の実測と食い違っています。

| | 2026-08-13（README記載） | 2026-08-15（本日） |
|---|---|---|
| 要求尺 | 74.182 s | 126.546 s |
| 配信尺 | 69.80 s（**切り戻す余地ゼロ**） | 126.546 s（122.182 sへ切り戻し成功） |
| 音楽終端 | 67.77 s → 約2秒の無音 | 122.1775 s（グリッド4ms手前） |
| `silent_gap` | blocking | **出ず** |

同じturboモデルで結果が違います。原因の候補は3つで、どれかは決まっていません。

1. PR #18 のガード既定化が効いた
2. 要求尺が長いとサーバの挙動が変わる（69.8 s付近に上限があった可能性）
3. あの日のインスタンス固有の問題

**確認手順**: vast.aiを起動し、8/13と同条件（74.182 s要求、seed 8、turbo）で1レンダー。
配信尺が要求どおりなら README の「常に」は成立せず、記述を実測に合わせて直します。
GPU 1レンダー分（数分）で決着します。
