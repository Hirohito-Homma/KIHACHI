# ADR-0010: レンダーを曲ではなく素材として扱う

**Status:** Accepted
**Date:** 2026-08-16

## Context

v0.1以降の測定は、一貫して同じ形を示している。**生成器が壊すのは時間をまたぐ設計だけ**である。

| 測定 | 結果 |
|---|---|
| コード進行の一致（完成ミックス） | 29テイク中18テイクで0.0、最大0.167 |
| 指定を反転させた対照テイク4本 | drums+bassは9割から動かない |
| tail guardの充足（同一設計・seed違い5本） | 4本がblocking、不足2.14〜3.82s |
| 整合スコアの振れ（seedのみ変更、5本） | 37.32〜77.52 |
| MIDIの進行（Live上で読み戻し） | **56小節中56小節一致** |

短い時間スケールの音色や質感は問題ない。壊れるのは、進行・セクション・尺という
**時間をまたぐ約束**である。そしてMIDIはそれを完全に運ぶ。

同じ失敗が、素材として使う場合には性質を変えることも重要である。

| 失敗 | 曲として | 素材として |
|---|---|---|
| キー・進行が違う | 修正不能 | 移調で直る、または捨てて次を採る |
| 低域偏重 | 修正不能 | stem分離済みの素材として使える |
| tailが届かない | 毎回賭け | 端を使わなければ無関係 |
| seedで大きく振れる | 原因の切り分け不能 | 単に採否の問題 |

## Decision

**ACE-Stepの出力を曲の完成品ではなく素材として扱う。**曲の構造はMIDIが運び、
生成器は音色と質感を供給する。

**短く焼くのではなく、中くらいに焼いて中央を切り出す。**2小節を要求することは、
生成器が最も苦手な領域（尺の端）へまっすぐ入ることを意味する。32小節でも
自分のグリッドに2.32s届かず、56小節でも5 seed中4 seedで足りなかった。
16〜32小節を焼いてその中央から切り出せば、冒頭の立ち上がりと、guardが届かない末尾の
両方を避けられる。

切り出しの契約は次の通り。

| 項目 | 規定 |
|---|---|
| 窓 | SongSpecの小節グリッド上。1始まり、終端は排他的 |
| 端 | 各端を最寄りのゼロ交差へスナップ。交差ペアのうち**ゼロに近い方**を選ぶ |
| スナップ上限 | 10 ms（110 BPMで1小節の0.5%）。届かない端はフェードし、その旨を記録する |
| 配置 | `<project>/audio/samples/<name>.wav` |
| 非破壊 | レンダーは読むだけ。モデルの挙動の証拠として残す |
| 素性 | プロジェクト、元AudioのSHA-256、seed、task_id、切り出した小節 |

**キーとBPMは「指定した値」として記録する。**測定値ではない。生成器がキーに従わないことは
測定済みなので、素材のメタデータがそれを保証しているかのように書くことはできない。

## Options Considered

### A. 中くらいに焼いて中央を切り出す（採用）

| Dimension | Assessment |
|---|---|
| tail guardの問題 | 触れずに済む |
| 冒頭の不安定さ | 避けられる |
| GPU時間 | 1テイク24秒（56小節、turbo）。使わない部分も焼く |
| 追加実装 | スライサーと素性の記録 |

### B. 2〜4小節を直接焼く

| Dimension | Assessment |
|---|---|
| tail guardの問題 | **最悪化する**（不足はほぼ一定なので、短いほど割合が大きい） |
| 冒頭の不安定さ | 素材の大部分を占める |
| GPU時間 | 短い |
| 追加実装 | 少ない |

### C. 曲として焼き続け、失敗テイクを捨てる

現状である。`shortlist`が選別を助けるが、進行・キー・構造は依然として設計どおりにならず、
選別で救えるのは「たまたま良かったテイク」だけである。

## Consequences

- 曲の構造はMIDI経路が担う。Live展開（ADR未採番、2026-08-16に実機確認）が本線になる。
- 生成器への要求が変わる。「この設計どおりの曲」ではなく「この質感の数小節」になり、
  進行やセクションの指示が通らないことは問題でなくなる。
- **`shortlist`の4次元は素材の選別に使えない。**duration・tempo・section_boundaries・
  section_energyはいずれもアレンジの整合を測るもので、4小節のループには意味がない。
  素材の選別指標は別に要る（未着手）。
- 素材をLiveへ持ち込む経路が要る。`import_vocal_take`がそれに当たるが、
  AbletonGPTの`import-kihachi`は現在この操作を受け付けない。**この設計を進めるなら、
  その契約を広げることが前提条件になる。**
- 中央を切り出せば端の問題は避けられるが、**素材が元から持つ不連続は引き継ぐ**。
  実際に切り出した4小節は、カットが作ったものではない`discontinuity` warningを含んでいた。
  切り出し後も`scan_material`で測ること。
