# ADR-0013: ブリーフは場所を言える。ただし半分単位で、密度についてだけ

**Status:** Accepted
**Date:** 2026-08-17

## Context

2026-08-17に語彙を8組へ広げた。すべて「何を」の語である。「どこで」は一語も無い。

一方`edit.py`は**v0.1から場所を解釈している**。`後半`／`前半`／`序盤`／`終盤`は
アレンジのspanへ解決され、セクション名やドロップ・ブレイクダウンも引ける。つまり
KIHACHIは**レンダーした後には場所を言えて、それを作るブリーフでは言えなかった**。
`syncopated`（PR #49）と同じ非対称で、同じ理由で直す価値がある。

既知の限界表に残っていた「`視界が開ける`のようなセクション間の対比」のうち、
対比そのものはPR #54が扱った。残りは**位置の指定**である。

## Decision

`Trait`に`scope`を持たせる。値は`first_half`／`second_half`／`None`（曲全体）。

**範囲語は`intent`へ移し、`edit`がそこからimportする。** 程度語（`少し`／`かなり`）が
先に同じ移動をしている。2つのリストがあると「後半」が2つのコマンドで違うspanを
指しうる。分割点も`edit`と同じ`len(arrangement) // 2`にする。

**scopeが付くのは`SCOPABLE_TRAITS`だけ**——`busy`／`sparse`／`contrast`／`flat`。
理由は単純で、**セクションごとに存在する値がenergyと3つのdensityしかない**からである。
`darkness`も`swing`も`note_length`も曲に1つの数であり、「後半だけ暗く」を
per-sectionで実現する置き場所が`SectionSpec`に無い。

**scopeの付かないtraitは拒否せず、曲全体に効く。**scopeが存在しなかった頃と同じ
挙動であり、そこで挙動を変えると「後半は暗く」と書いた既存のブリーフが黙って
別の曲になる。代わりに`brief`のカバレッジが**範囲語を未読として報告する**：
「後半は暗く」では`後半`にscopeが立たないので、読まれた語として数えない。
届かなかった指定を「届いた」と言わないことがこのモジュールの仕事である。

**曲全体の数値は`traits.unscoped()`だけを読む。**「後半は手数を多く」が
`drums.kick_density`（曲のキット）を上げてしまうと、前半も一緒に上がる。

## Consequences

* 範囲語の無いブリーフは1音も変わらない。`unscoped()`は全traitを返す。
* 「前半は淡々と、後半は手数を多く」でテクノ32小節のセクション別音数は
  130/167/184/196 → 130/159/224/223。前半は縮み、後半は増える。
* 「終盤だけスカスカに」は後半2セクションだけを下げる（184/196 → 151/158）。
* scopeは**節ごと**に読む。否定と同じで、読点を越えない。「前半は淡々と、後半で
  メリハリを」は2つの場所についての2つの文である。

## What this does not cover

* **「ここで視界が開ける」は依然として読めない。**`ここ`は場所を指す語ではなく、
  文脈が指す場所である。半分単位の語しか無い以上、これは読めないままにする方が
  正しい。
* **セクション名での指定**（「ドロップで」）。`edit`は引けるが、ブリーフの時点では
  アレンジがまだ存在せず、どの名前のセクションが生成されるかも決まっていない。
  順序が逆なので、同じ語彙をそのまま持ち込むことはできない。
* **3分割以上**（「中盤」）。分割点を`edit`と共有している以上、片方だけ増やすと
  また2つの意味ができる。増やすなら両方で同時に。
* **曲に1つしかない数値のscope**（「後半だけ暗く」）。`SectionSpec`に置き場所を
  作る変更であり、それはこのADRより大きい。
