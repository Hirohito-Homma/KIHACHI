# ADR-0014: スイングは拍を歪ませる。一部の音符を遅らせるのではない

**Status:** Accepted
**Date:** 2026-08-18

## Context

PR #61で12/8のシャッフルを`swing_for_offbeat(2/3)`に直し、オフビートは正しく
0.667に来るようになった。2026-08-18にブルースを1曲composeしてLiveに送り、
Chordsをソロにして鳴らしたところ、**コードが二度打ちして濁っていた**。

原因は`composer._groove`の位置判定である:

```python
subdivision = int(round(start * 2))
swing_delay = ... if subdivision % 2 else 0.0
```

この式は**8分グリッドしか名指していない**。16分位置は丸めで潰れる:

| 位置 | `int(round(start*2))` | 解釈 | スイングされるか |
|---|---|---|---|
| 0.0  | 0 | ダウンビート | されない（正） |
| 0.25 | 0 | **ダウンビート** | **されない（誤）** |
| 0.5  | 1 | オフビート | される |
| 0.75 | 2 | **次の拍** | **されない（誤）** |

結果、16分を書くパートはスイングした8分（0.667）とストレートな16分（0.75）を
**1/12拍差**で並べた。シャッフルではなくフラムである。ブルースのchordsは224音
すべてがこの2か所に乗っていた。Live側の`analyze_live_midi_clip`は推定グリッドを
`0.0625`（64分）と報告する — 0.083拍差を説明するために刻みが落ちた数字であり、
きれいなシャッフルなら0.333か0.167になる。

**既存のテストは全部通っていた。** `test_groove.py`の3つはいずれも「8分が動いたか」
を訊いており、8分は実際に動く。PR #61と同じ構図で、Liveで鳴らすまで出なかった。

## Decision

`_groove`の二値判定を捨て、**拍内位置の連続的なワープ**に置き換える
（`composer.swung_position`）。

```
offbeat = 0.5 + max(0, swing - 0.5) * SWING_REACH_BEATS
position < 0.5:  position * (offbeat / 0.5)
position >= 0.5: offbeat + (position - 0.5) * ((1 - offbeat) / 0.5)
```

直線2本で、拍の前半と後半をオフビートを軸に伸縮させる。`groove.swing`が実際に
名指しているのはオフビートの位置だけで、**それ以外の位置は決め打ちではなく
そこから導かれる**というのがこの決定の中身である。

* 0と1は不動。**拍が隣の拍から借りない。**
* `swing = 0.5`ではoffbeat = 0.5となり両方の直線が恒等写像。ストレートな曲の
  出力は1バイトも変わらない。
* 8分（0.5）の挙動は従来と完全に一致する。`SWING_REACH_BEATS`を使った
  「leanであってpositionではない」という既存の考え方（PR #61）はそのまま残る。
* 三連シャッフルでは16分が**6連（sextuplet）**に乗る: 0.25 → 1/3、0.75 → 5/6。

## 6分割であって3分割ではない

回帰テストの判定基準を三連グリッド（1/3）にすると、**正しい修正まで落ちる**。
シャッフルした拍は3分割なので、16分はそこに自分のスロットを持たない。スイング
した8分（4/6）とその両隣の16分を同時に収められる最も粗い分割が6である。

テストは「16分がどこに来るべきか」は主張しない。それは設計の問題であって、
テストが決めることではない。主張するのは**書かれたグリッドが1つであること**
だけである。0.25と0.75はシャッフルした拍のどの分割にも乗らない。

## Consequences

**ゴールデンMIDIは3トラックとも再ピン留めした。** `mutation-signal-lora`は
`swing 0.54`で、その16分はこれまでストレートに置かれていた。110 BPMで3.82ms
動く。拍と8分は1ティックも動かない。

**スイングする曲はすべて出力が変わる。** ストレートな曲（1021ジャンル中の大半）
は不変。変わるのは`mutation_funk`、12/8を読むBlues 28行、そしてブリーフで
`swung`を指定した曲である。

**この決定が触れないもの:**

* `groove.swing`の意味と範囲。leanのままである。
* `BASS_POSITIONS`と`ARP_GRID`。16分グリッドを書くこと自体は変えない。
  それをどう鳴らすかだけを変えた。
* `groove.py`の`groove_report`。これは音声解析側の指標で、**同じ8分前提を
  共有している**（オフビートを8分から測る）。16分の位置を測る道具は無いままで、
  今回の不具合を音声から検出することは依然できない。次に同種のバグが出たら、
  やはりLiveで鳴らすまで分からない。

**教訓はPR #61と同じで、より一般的な形になる:** 「値が動いたか」を訊くテストは、
動く値が1つでもあれば緑になる。訊くべきは「書かれた結果が音楽として1つの
グリッドに乗っているか」である。
