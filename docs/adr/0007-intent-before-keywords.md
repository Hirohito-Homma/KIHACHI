# ADR-0007: 指示は「特性・極性・強度」として読む

**Status:** Accepted
**Date:** 2026-08-10

## Context

`MusicBrain.analyze`はプロンプトに対して5つの真偽判定（`"スラップ" in prompt`など）を行い、その答えごとに2つの定数のどちらかを選んでいた。ここには性質の異なる2つの欠陥があった。

**否定が要求として読まれていた。** `"スラップじゃなくて指弾きで"`は部分文字列`スラップ`を含むため、判定は真を返し、bassの4パラメータ（technique / syncopation / octave_jump / ghost）が要求と正反対に設定される。`"サイケじゃない"`は`style.psychedelic`を最大値0.82にした。これは機能不足ではなく**正しさの欠陥**である。明確に述べられた拒否が、その逆の指示として実行されていた。

**強度の置き場がなかった。** `少しサイケ`と`かなりサイケ`はどちらも0.82になる。真の側に0.82しか存在しないため。皮肉なことに語彙は既に`edit.py`にあり（`SMALL_WORDS` / `LARGE_WORDS`）、**曲を直すときだけ**機能して**曲を頼むときには**機能しなかった。同じ日本語が、打ったコマンド名によって通じたり通じなかったりしていた。

加えて、読み取れた場合でも着地点が定数しかなかった。`drums.kick_density` 0.72、`groove.humanize` 0.18、`harmonic_rhythm_bars` 1、`bass.role`、`chords.articulation`は1020ジャンル全てで同一だった。

## Decision

- **`intent.py`を新設**し、プロンプトを`Trait(name, polarity, strength)`へ分解する。極性と強度は解釈層の責務とし、そこから何を導くかは呼び出し側の判断として残す。
- **否定は言語ごとに向きが違う**ため、日本語は直前の言及へ、英語は直後の言及へ結びつける。列挙（`"スラップとサイケはなし"`）は接続語のみで繋がれている場合に限り拡張し、`"ミニマルにしてサイケは無し"`は後者だけを拒否する。**節境界を越えない。**
- **拒否は「低い極」に着地させ、その先へは行かない。** ここで扱う全ての特性について、拒否された側の値は言及が無いときに使われていた値そのものであり、それを下回る値を作るのは解釈ではなく捏造になる。否定が買うのは新しい値ではなく、**反対の値に着地しなくなること**である。
- **強度1.0を「素の言及」と定義**し、`blend(low, high, 1.0) == high`とする。highは従来ハードコードされていた定数そのものなので、強度語も否定語も含まないプロンプトの出力は**1ビットも動かない**。これは`preferences`で採用した「中立は恒等写像」と同じ規律である。
- 度合いの語彙とマッチ判定（ASCII語は語頭境界、日本語は部分一致）は`intent.py`が保持し、`edit.py`はそれをimportする。編集側のmagnitudeは変更しない。
- **`derive.py`を新設**し、家族（37 families）単位の手書きテーブルで凍った定数を解凍する。データベースが持たない属性をデータベースから導いたふりはしない。

## Consequences

- `example_output`のSongSpecとそのSHA-256、既存のrepaint/chunk計画は影響を受けない。既存プロンプトが否定も強度も含まないことがそれを保証している。
- **既定値は中立ではなかった**という事実が明示される。`FAMILY_PROFILES`の先頭行（R&B / Soul / Funk）は今日の定数そのものであり、これは全ジャンルが一つのジャンルの数値を受け取っていたことを言語化したものである。
- **ASCII語の判定が僅かに狭まる。** 従来の素の部分一致では`overloaded`が`lead`に一致していた。語頭境界を要求することでこれは一致しなくなる。認識が減る変更だが、減るのは誤検出のみであり、固定済みプロンプトは影響を受けない。
- **`drums.hat_density`は解凍しない。** `composer.py`が0.3の閾値で8分/16分の2値に量子化しているため、それ以上の値は全て同じMIDIを生む。ここで動かしても変わるのはプロンプト文字列だけで、制御しているように見えて制御していない状態になる。composer側の連続化は別の変更とする（ADR-0006と同様、データが支えない実装は見送る）。
- 否定の解決は構文解析ではなく近接規則であるため、限界がある。`"サイケは要らないがミニマルにして"`のような逆接を跨ぐ表現は誤る余地が残る。誤る方向は**常に肯定側**（＝従来の挙動）に倒れるよう構成した。
