# ADR-0009: 候補順位付けの境界

**Status:** Accepted
**Date:** 2026-08-16

## Context

v0.2の残項目に「複数候補の音楽的な自動採用」がある。stem分離で確定した事実
（ADR-0008、および README の「指定した和音進行・キーが鳴らない」）により、
**プロンプトで結果を操作できない**ことが分かった。指示が効かない以上、
複数テイクを焼いて選ぶ側が実質唯一のレバーになる。

一方、既存の順位付けは`report.rank()`と`revision.ranked()`の
`(blockingな欠陥, 整合度)`だけである。これには2つの穴がある。

- **なぜ勝ったかを言えない。**スカラー1本なので、決め手になった次元が分からない。
- **差の大きさを扱えない。**0.3点差と20点差が同じ「1位」として出る。
  整合度の成分は1レンダーから推定した比率であり、小数第1位の差は根拠が薄い。

さらに、動かない次元がweightを持ち続ける失敗が実際に起きている。review v0.1は
`key`と`chords`に合計0.45を割いていたが、`example_output`の25テイクを集計すると
`key`は全19テイクで定数0.350、`chords`は0.000〜0.098だった。v0.4で両方を外したが、
**後から集計して気づいた**ものであり、同じ失敗は別の成分でも起こりうる。

## Decision

**採用しない。順位と根拠だけを出す。**

`shortlist`は`take_shortlist.json`を書き、`decide`コマンドを表示して終わる。
`decision_log.json`へは書かない。ADR-0005（Reviewは何も変更しない）と
`decision.py`（採用は人間の試聴判断）の境界を、候補が2本から6本になっても動かさない。

判断の規則は2つ。

| 規則 | 規定 |
|---|---|
| 判別力 | 各次元をその候補集合内で先に測る。ばらつきが`spread_floor`（0.05）未満なら`flat`、ゼロなら`constant`として表示し、weightに関わらず根拠から外す |
| 有意差 | 上位2本の差が`margin_floor`（3.0点）未満なら勝者を名指しせず`too_close_to_call`とする。**全次元が動かない場合も同じ扱い**（順位付け不能ではなく、最も強い同着） |

生き残った次元でweightを再正規化する。しないと、1次元しか動かない集合で全員の得点が
ゼロ近辺に潰れ、順位はついているのに数字が読めなくなる。

比較可能性はADR-0005の規則を3本以上へ広げる。`song_spec.json`の正規化ハッシュが
一致しないテイクは`different_song_spec`として除外する。未スキャンは`not_scanned`、
blocking欠陥は`blocking_defect`。

warning欠陥は**得点に入れない**。同着のときだけ`tie_break`として最も少ないテイクを添える。
warningは閾値付近の測定値であり、repaintがクリックを移動させた実測例がある以上、
点数を与えるには足りない。

`spread_floor`と`margin_floor`は**宣言した床であって、測定したノイズではない**。
その旨を出力JSONに書き、後から実測値へ置き換えられるようにする。

## Options Considered

### A. 順位と根拠のみ。採用は`decide`（採用）

| Dimension | Assessment |
|---|---|
| 既存境界 | ADR-0005・`decision.py`と整合する |
| 誤判定の代償 | 小さい（人が聴いて覆せる） |
| 測れない次元の扱い | 明示して残せる |
| 手間 | 試聴が必要 |

### B. `--adopt`で任意に自動採用

| Dimension | Assessment |
|---|---|
| 既存境界 | `decision_log.json`に試聴していない`reason`が入る |
| 誤判定の代償 | 大きい（音色・歌唱を無視した採用が記録として残る） |
| 手間 | 少ない |

### C. 常に自動採用

Bの欠点がすべて既定になる。測れない次元（音色、歌唱、音楽的な面白さ）が
本番の選択基準から恒久的に落ちる。

BとCは、判断根拠の質が上がってから改めて検討できる。Aの出力はその材料になる。

## Consequences

- 「どれが1位か」に加えて「何が決めたか」「その差は意味があるか」が残る。
- 動かない次元がweightを持ち続ける失敗が、次に起きたときは出力に出る。
  `key`の0.350を見つけるのに要した後追いの集計が不要になる。
- 候補が全て同点のとき、システムは「選べない」と言う。これは正しい答えであり、
  無理に順位をつけるより有用である。
- 試聴は依然として必要である。`not_judged`（音色、歌唱、音楽的な面白さ、
  ハーモニーの当否）は出力に必ず並ぶ。
- 床の値2つは暫定である。同一設定・別seedのテイクを複数焼いて成分のばらつきを測れば、
  実測値へ置き換えられる。
