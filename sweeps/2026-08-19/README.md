# 2026-08-19 sweep — 30ブリーフと、その日のモデルの読み

`intent.read`（ルール）と `intent read`（モデル）の2つの読み手を突き合わせるための
コーパスです。**保存済みの読みなので、比較はオフラインで無料**です — ブリーフは
`intent_reading.json` の中に入っており、`brief_sha256` が取り違えを弾きます。

```bash
python3 -m kihachi_music_ai compare-readings sweeps/2026-08-19/readings/s01
```

`tests/test_sweep.py` が30件すべてを回し、**既知の8件の不一致だけが残っていること**を
テストします。`intent.py` を変えたら手で回す必要はありません — 不一致が増えても減っても
落ちます。減った場合は、そのエントリを同じコミットで消して、**どちらの読み手が動いたか**を
コミットメッセージに書いてください。

## 中身

| ファイル | 何か |
|---|---|
| `briefs.tsv` | 1行1ブリーフ、2列目はそのブリーフが狙っている文法（`added tail + compound tail` など） |
| `readings/s01..s30/intent_reading.json` | 同じ順で、`claude-opus-5` が返した読み（ADR-0011のスキーマ、検証済み） |

## なぜリポジトリに入っているか

これ以前のsweepは**すべてセッションのスクラッチに書かれて消えました**。そのため
`intent.py` を触るたびに、既に存在していたコーパスに再課金し、その変更が閉じ*なかった*
不一致は散文か記憶にしか残りませんでした。1ブリーフあたりモデル呼び出し1回で、
比較はその後ずっと無料です。監査対象のコードと同じ場所に置いておくのが安いという判断です。

## この30件が見つけたもの

9件の不一致のうち**3件が本物のルールのバグ**でした — する否定（#91）、拒否が
「拒否する語を修飾する語」に届いていなかった件（#92）、そして修正できない語彙の限界
（`アルペジ` と `シーケンス` が同じ `arp` trait）。2件は**モデル側が誤り**、2件は
「め」の読みのばらつき、2件は既知としてピン留め済みです。

残る8件の理由は `tests/test_sweep.py` の `KNOWN` に1件ずつ書いてあります。

**strength の差は3〜5回読み直してから判断してください。**「暗めにして。」は5回で
1.0, 1.0, 0.5, 0.5, 1.0 と割れました。polarity の差は今のところ毎回再現しています。
